### Strategic DDD — Bounded Context & Cơ chế giao tiếp
- **Bounded Context:** Ranh giới phân chia hệ thống lớn thành các phân vùng độc lập. Ví dụ: Order Context, Inventory Context, Payment Context.
- **Command (Sync) vs Domain Event (Async):** Bạn tự suy luận ra rằng Order → Inventory phải sync (tránh over-selling), Payment/Notification/Fulfillment nên async.
- **Inventory Reservation:** Bạn giải thích đúng: nếu không giữ kho ngay, 11 user thấy còn 10 sản phẩm nhưng thanh toán thì 1 user bị lỗi.
- **Saga Pattern (cơ chế lõi):** Chuỗi bước độc lập + Compensating Transaction. Bạn tự nêu đúng: hết 15 phút không thanh toán → phải khôi phục tồn kho + chuyển đơn sang trạng thái thất bại.

### Hexagonal Architecture (Ports & Adapters)
- 3 tầng: Domain (luật + Port interface) → Application (điều phối luồng) → Infrastructure (Adapter implement Port).
- **Nhầm lẫn đã sửa:** Bạn ban đầu nghĩ Application = Port → đã được giải thích lại.
- **IoC Container:** Spring Boot đóng vai trò quyết định lúc runtime Port dùng Adapter nào (tương tự main() trong Java thuần).

### Tactical DDD — Entity, Value Object, Aggregate, Repository
- Các khái niệm được seed (định nghĩa) nhưng chưa Feynman pass do buổi kết thúc sớm.

### Lỗ hổng phát hiện trong buổi

- Bạn nhầm Application là Port → đã sửa.
